# ハーネス共通仕様の取り込み状況

## 参照元と対象

- 参照先：[ysteam0117/harness](https://github.com/ysteam0117/harness)（公開リポジトリ）
- 対象：AI-Memoryの既存MVP 1開発基盤
- 実施方法：**共通仕様を調査して手動で反映**。公式CLIの`harness adopt`を実行したものではありません。
- 根拠資料：`docs/requirements/common/`の設計・Frontend・Backend・品質・セキュリティ・ワークフロー文書

AI-Memory固有の条件定義書 v8.8 と原本・機密情報の保護を優先し、外部プロジェクトの一般的な構成やCloudflare向け構成を無条件に導入しません。

## 見送った項目と理由

- **harness CLIによる一括導入**：既存のAGENTS・CI・DB設計を置き換えたり競合する可能性がある。差分のレビューを優先。
- **Axios、Zod、TanStack Query、React Hook Formなどの新規依存**：現在の画面はヘルスチェックのみ。追加が必要になった時点で根拠・セキュリティ・ロックファイルを確認する。
- **Cloudflare/D1、外部認証・クラウド向けのひな形**：AI-MemoryはWindowsローカルのSQLite・WebAuthnを前提とするため、そのまま移植しない。
- **E2E・SAST・DAST・セキュリティ監査ツール等のフルセット**：別の品質基盤PRで段階的に導入し、未実施の検査を実施済みとは記載しない。
- **自動的な本番DB移行、原本を用いたCIテスト**：AI-Memoryのデータ保護要件に反するため導入しない。

## 次に取り組むこと

1. `package-lock.json`の固定、`npm ci`への切り替え、依存脆弱性警告の調査。
2. 品質チェック（Prettier・ESLint・型チェック・テスト）の追加。
3. APIエラー応答、ログの記録先、認証・認可仕様の整備。
4. 本番ではなく合成データによる単体・結合・E2E検証の充実。

利用するハーネスの仕様とAI-Memoryの仕様が矛盾したら、自動で一方を採用せず、相違点を示してレビューします。
